# AI 与数据流水线 · 开发计划

> 原则：**每个阶段都产出可运行、可验证的东西**，先小步跑通再逐步加深。

## 阶段一 · 单次调用

- **目标**：跑通
- **产出**：一个调用脚本

- [ ] 配置 key 与地址
- [ ] 发一次请求
- [ ] 打印结果

## 阶段二 · 批量处理

- **目标**：成规模
- **产出**：批量任务脚本

- [ ] 并发控制
- [ ] 重试与限流
- [ ] 结果落盘

## 阶段三 · 加检索

- **目标**：有知识
- **产出**：带向量检索的流程

- [ ] 切片与嵌入
- [ ] 向量入库
- [ ] 相似召回

## 阶段四 · 编排

- **目标**：可交付
- **产出**：多步 Agent 流水线

- [ ] 工具调用
- [ ] 多步流程
- [ ] 定时执行

### 里程碑与验收

| 阶段 | 验收标准 |
|---|---|
| 阶段一 · 单次调用 | 一个调用脚本 |
| 阶段二 · 批量处理 | 批量任务脚本 |
| 阶段三 · 加检索 | 带向量检索的流程 |
| 阶段四 · 编排 | 多步 Agent 流水线 |

> 建议：每完成一个阶段就在本目录下建一个具体项目子目录，把成果固化下来。
