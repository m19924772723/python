# 运维与命令行脚本 · 开发计划

> 原则：**每个阶段都产出可运行、可验证的东西**，先小步跑通再逐步加深。

## 阶段一 · 能跑的脚本

- **目标**：跑通
- **产出**：带参数的脚本

- [ ] 读参数
- [ ] 执行逻辑
- [ ] 打印结果

## 阶段二 · 抽成 CLI

- **目标**：好用
- **产出**：多子命令工具

- [ ] 子命令拆分
- [ ] 帮助信息
- [ ] 优雅输出

## 阶段三 · 稳与可观测

- **目标**：可靠
- **产出**：带日志的工具

- [ ] 日志与级别
- [ ] 异常兜底
- [ ] 失败重试

## 阶段四 · 自动化

- **目标**：无人值守
- **产出**：定时运行的作业

- [ ] 接入计划任务
- [ ] 结果通知
- [ ] 写使用说明

### 里程碑与验收

| 阶段 | 验收标准 |
|---|---|
| 阶段一 · 能跑的脚本 | 带参数的脚本 |
| 阶段二 · 抽成 CLI | 多子命令工具 |
| 阶段三 · 稳与可观测 | 带日志的工具 |
| 阶段四 · 自动化 | 定时运行的作业 |

> 建议：每完成一个阶段就在本目录下建一个具体项目子目录，把成果固化下来。
